# Модель рыночных данных

## MarketOffer

`MarketOffer` описывает одно ценовое предложение:

| Поле | Значение |
|---|---|
| `id` | Уникальный ID предложения в рамках ECOInter |
| `serverId` | Сервер Eco, на котором доступно предложение |
| `itemId`, `itemName` | Идентичность и отображаемое имя товара |
| `action` | `buy` — пользователь покупает; `sell` — пользователь продаёт |
| `currency` | Валюта конкретного предложения |
| `totalPrice` | Сумма за весь лот `quantity` |
| `quantity` | Доступное целое количество предметов |
| `quoteKind` | `listing` или `reference` |
| `observedAt` | Время наблюдения источником |
| `sourceId` | Идентификатор источника |

Не следует объединять одинаковые названия товаров с разных серверов без идентификатора или подтверждённого пользовательского соответствия.

## Семантика цен

В нормализованной модели цена задаётся суммой за лот. Средняя стоимость единицы вычисляется как `totalPrice / quantity` с фиксированной точностью. Полный лот использует исходную общую сумму без обратного округления. При частичном исполнении стоимость покупки округляется вверх, а выручка от продажи — вниз до минимальной денежной единицы, чтобы не завышать прибыль.

`buy` и `sell` — действия пользователя, а не свойства страницы GoodPrice. В адаптере реального API нужно доказать, какая колонка/поле соответствует покупке и какая — продаже.

## Валюты

Валюты хранятся как отдельные строки. Арифметика не складывает значения разных валют. Единственный переход между валютами в аналитике — подтверждённая последовательность покупки и продажи одного и того же товара на одном сервере.

## Уровни достоверности

- `listing`: источник передал предложение с количеством и ценой. Это более сильное основание для потенциального исполнения, но котировку всё равно нужно перепроверять непосредственно перед сделкой.
- `reference`: справочная или усреднённая величина; результат только оценочный.
- `interserver`: разница цен между серверами не образует исполнимого маршрута без подтверждённого механизма перемещения активов.

## Денежная точность

Деньги представлены десятичными строками на границе API и `bigint` с масштабом `10^8` внутри движка. `Number` используется только для количества целых предметов и интерфейсного форматирования, а не для денежной арифметики.
