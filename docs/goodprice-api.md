# GoodPrice API — интеграция

## Источник схемы API

Реализация опирается на независимый проект [ECO-GoodPrice-Trader](https://github.com/CodeWithCharles/ECO-GoodPrice-Trader), в котором опубликованы клиент GoodPrice, разбор ответов плагина, примеры реальных снимков и тестовые фикстуры:

- [Описание API и полей](https://github.com/CodeWithCharles/ECO-GoodPrice-Trader/blob/bf88ab57abb1e24f1eb348f062d74e36f9189d14/docs/api-goodprice.md)
- [HTTP-клиент](https://github.com/CodeWithCharles/ECO-GoodPrice-Trader/blob/bf88ab57abb1e24f1eb348f062d74e36f9189d14/src/ecotrade/client.py)
- [Нормализация магазинов и предложений](https://github.com/CodeWithCharles/ECO-GoodPrice-Trader/blob/bf88ab57abb1e24f1eb348f062d74e36f9189d14/src/ecotrade/market.py)

Это независимая обратная разработка с примерами ответов сервера. Она позволяет реализовать адаптер, но сама по себе не доказывает, что конкретный сервер пользователя доступен или использует ту же версию плагина. Поэтому первая проверка в ECOInter должна подтвердить фактический ответ именно этого адреса.

## HTTP API

Для заданной пользователем страницы вида:

`http://HOST:PORT/plugin/GoodPrice`

адаптер формирует запрос:

`GET http://HOST:PORT/api/v1/plugins/GoodPrice/stores`

Заголовки:

| Заголовок | Значение |
|---|---|
| `Accept` | `application/json` |
| `X-Auth-Token` | GoodPrice world ticket |
| `Content-Type` | `application/json` (при отправке токена) |

Для авторизации используется заголовок `X-Auth-Token`. Это не токен авторизации игрового сервера Eco и не пароль аккаунта.

### Где взять world ticket

Открой GoodPrice в игре и открой инструменты разработчика встроенного браузера. В разделе **Application → Local Storage** найди ключ `worldTicketData`; в сохранённом объекте нужен параметр `worldTicket`.

По документации независимого клиента срок действия токена — примерно 24 часа. При ответе HTTP 401/403 обнови токен в карточке сервера ECOInter.

Не отправляй world ticket в переписку и не публикуй его в логах или скриншотах.

## Структура ответа /stores

Успешный ответ имеет верхнеуровневое поле `Stores` — массив магазинов. Для каждого магазина используются:

- `Name`, `Owner`, `Balance`, `CurrencyName`, `Enabled`, `FullAccessUsers`;
- `AllOffers` — массив предложений.

Поля предложения:

- `ItemName` — название предмета;
- `Buying` — направление сделки магазина;
- `Price` — цена за одну единицу;
- `Quantity` — количество/остаток;
- `MaxNumWanted` — объём спроса магазина;
- `Enabled` — включено ли предложение;
- `Limit`, `MinDurability` — дополнительные поля.

### Нормализация

ECOInter переводит ответ GoodPrice во внутренний контракт `ecointer.market.v1`:

| GoodPrice | ECOInter |
|---|---|
| `Buying: false` | `action: "buy"` — игрок покупает у магазина |
| `Buying: true` | `action: "sell"` — игрок продаёт магазину |
| `Price` | цена за единицу; при нормализации умножается на доступное количество |
| `Quantity` у магазина-продавца | доступный остаток |
| `MaxNumWanted` у магазина-покупателя | объём спроса |
| `CurrencyName` | валюта магазина |
| `Name` | источник предложения и название магазина сохраняется в рамках текущей модели через нормализованные идентификаторы/метаданные |

Пустые слоты с `ItemName: null`, отключённые предложения, нулевые количества, нулевые цены, а также sell-слоты с sentinel-ценой `999999` исключаются. Теги вида `<color=...>` удаляются из названий. Предложения покупки из магазинов с нулевым балансом исключаются.

Внутренняя модель ECOInter хранит `totalPrice` за всё количество, а не цену единицы. Это важно для точной арифметики движка. При импорте снимка цены пересчитываются с десятичной точностью до восьми знаков.

## Что сейчас делает адаптер

- Проверяет именно API endpoint `/stores`, а не только HTML-страницу плагина.
- При наличии токена передаёт его только в `X-Auth-Token`.
- Отличает отсутствие токена/истёкший токен (401/403), отсутствие endpoint (404), не-JSON и неожиданный формат ответа.
- Нормализует магазины и предложения в модель ECOInter.
- Сохраняет текущий стакан и историю наблюдений в локальной SQLite.
- Позволяет запустить синхронизацию вручную и периодически обновляет подключённые серверы по настроенному интервалу.

**Ограничение проверки:** код интеграции основан на описанной выше независимой реализации. Запрос к конкретному серверу пользователя должен быть проверен его токеном. Пока в карточке сервера не показано «Рынок синхронизирован» и число импортированных предложений, нельзя считать получение его рынка подтверждённым.

## Ограничения API

Согласно независимому исследованию GoodPrice, API не предоставляет:

- временную метку создания/последнего обновления отдельной котировки;
- историю фактических транзакций;
- расположение магазинов и расстояние до них;
- вес предметов.

Поэтому ECOInter присваивает снимку время его получения. История цен начинается с момента первой синхронизации, а не восстанавливается задним числом. При планировании маршрутов нельзя считать известными расстояние, вес и реальный оборот магазинов.

Баланс магазина относится к кошельку владельца, а не отдельной торговой точке. Если один владелец держит несколько магазинов, нельзя суммировать их балансы как независимые средства. Текущая версия ECOInter фильтрует магазины с нулевым балансом, но пока не моделирует общий остаток кошелька между несколькими его магазинами; результаты, затрагивающие такие магазины, требуют дополнительной проверки.

## Безопасность

World ticket хранится в локальной базе в зашифрованном виде AES-256-GCM. Ключ создаётся автоматически в `data/master.key`; вручную генерировать или вводить мастер-ключ не требуется.

В исходном URL пользователя используется HTTP. HTTP не шифрует сетевой трафик, поэтому world ticket может быть перехвачен в сети. Используй это подключение только в доверенной сети либо настрой HTTPS перед передачей токена.
